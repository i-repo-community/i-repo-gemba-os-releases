# 更新情報（What's New）

アプリの主な改善・修正をまとめます。最新の配布物は
[ダウンロード（最新リリース）](https://github.com/i-repo-community/i-repo-gemba-os-releases/releases/latest)
から入手できます。

## 2026年8月

### 新機能: 現場 AI チャットが AI の API へ直接つながります（v0.47.0）

Claude Code などの CLI を導入しなくても、Anthropic / OpenAI の **API キーだけ**で
現場 AI チャットが使えるようになりました。チャット画面の「＋新しいチャット」の横の
⚙ ボタン（または入力欄の「速い ▾／API: …▾」メニューの「接続設定…」）から
画面の案内に沿って設定できます。

- API キーはこのアプリの中にだけ保存され、選んだ会社（Anthropic / OpenAI）の API への
  認証にだけ使われます。キーの中身が画面に表示されることはありません
- 手元の Claude Code / Codex CLI を使う従来の方式にも、いつでも切り替えて戻れます
  （切り替えると新しいチャットが始まります）
- API 直接接続では、帳票の PDF・添付画像の参照はまだできません（検索・集計・明細の
  読み取りはできます）。プロジェクトチャット（ファイルの作成・編集を伴うもの）は
  従来どおり CLI で動くため、CLI の導入が必要です
- 推論にかかる料金は、設定した API キーのアカウントに従量でかかります

### 実験的な機能: CLI Studio — 現場データと i-repo CLI について AI に相談できます（v0.46.0）

現場のデータで何が分かるか・i-repo CLI でどう調べるかを、AI と会話しながら確かめられる
コーナーを実験的に追加しました。**既定では表示されません**。設定画面の最下部
「実験的な機能」で有効にするとメニューに現れます。

- 読み取り専用です。相談から配信先データや i-Reporter が書き換わることはありません
- CLI の使い方の質問には、**お使いの導入版の実物のヘルプ**と同梱の読み取り規約を
  根拠に答えます（記憶に頼った不正確な回答を防ぐ仕組みです）
- 実験的な機能のため、画面や挙動は予告なく変わることがあります

### 新機能: 現場スキルを AI エージェントのプラグインとして書き出せます（v0.45.0）

プロジェクト画面の「プラグインとして書き出す」から、人が確認済みの現場スキル・
データの読み方の基盤スキル・MCP 接続を1つのプラグインに束ねて書き出せるようになりました。
Claude Code / Codex / Cursor にそのまま読み込ませると、エージェントが「この現場の帳票の
読み方・決まりごと」を知った状態で仕事を始められます。

- **1つのパッケージを3クライアントが読めます**: Claude Code / Codex（0.145.0 以降）/
  Cursor。業界標準（agent-plugins 1.0.0）形式で、macOS / Windows の実機で動作確認済みです
- 書き出し先はプロジェクトフォルダの `.agents/plugin-export/`（フォルダと zip の両方）。
  **現場の知識を含むため、公開の場（公開リポジトリ・マーケットプレイス等）には
  置かないでください**（書き出し時にもアプリが注意を表示します）
- 現場スキルを更新したら、再書き出し＋クライアント側の再インストールで反映されます
- 読み取り専用です。プラグイン経由のエージェントが配信先データや i-Reporter を
  書き換えることはありません

### 改善: AI エージェント向け接続の健全性応答が正確になりました（v0.45.0）

蓄積データへの MCP 接続の健全性確認（gemba_health）が、読み返しプラグインの実体が
見つからない場合にそれを正しく報告するようになりました（従来は実体がなくても
正常応答になっていました）。

### 新機能: 未変更の帳票の再ダウンロードを省略できます（v0.44.0）

安全取得の設定に「未変更の帳票のダウンロードを省略」を追加しました。前回の配信から
内容が変わっていない帳票の PDF 等を、毎回取り直さずに済みます。夜間の無人バックフィルや
ファイルサーバーへの定期保管で、転送量と実行時間を削減できます。

- 省略された帳票も記録には残ります: 各バッチには実ファイルの代わりに「前回の配信物への
  参照」が記録されるので、あとから辿れます
- 設定をオンにしても条件が合わない実行（初回・複数配信先など）では、従来どおり全件取得し、
  その理由が実行ログに1行記録されます（黙って省略されない）

### 改善: 一時的な通信エラーに自動で再試行します（v0.44.0）

安全取得フローの設定に「一時エラーの再試行回数」を追加しました。夜間の無人取り込みが、
一過性のネットワークエラーやサーバ側の一時的な応答不良で止まりにくくなります。

### 改善: 結果レポートに帳票ごとの失敗明細が出ます（v0.44.0）

結果レポート（完了報告書）の明細 CSV に、**どの帳票が・なぜ**失敗したか／検証で
見つからなかったかを、帳票単位の行と理由列で出力するようになりました。件数の上限を
超えた場合は、その旨がレポート本文に明示されます。

### 新機能: 実行時間帯ウィンドウ — 夜間だけ取り込む運用ができます（v0.43.0）

安全取得のチャンク実行を、指定した時間帯（例: 22:00〜06:00）だけに限定できるように
なりました。営業時間中にサーバへ負荷をかけたくない現場のバックフィル運用向けです。

- **スケジュール実行にだけ効きます**: 手動実行はいつでも可能です（時間帯外だった
  ことは実行ログに記録されます）
- **実行中に時間帯を外れたら、きりの良いところで停止**: 処理済みの分は確実に記録され、
  残りは次回の実行が続きから進めます
- 時間帯外にスケジュールが発火した場合は、その日の実行はスキップされます（保存時に
  「スケジュール時刻が時間帯外です」と警告します）

### 新機能: 見積もりレポートと結果レポート（v0.43.0）

バックフィル（過去からの遡及取得）の計画立案と完了報告を、ファイルとして残せるように
なりました。

- **見積もりレポート（計画書）**: フロー編集の「見積もりを作成」から、月別の件数表と
  所要時間の目安（構造的な下限と、実績がある場合の参考値）を Markdown + CSV で出力します
- **結果レポート（完了報告書）**: 実行詳細の「レポート出力」から、何件届き・何が失敗
  したか（チャンク別内訳・配信先別の検証状況）と、帳票ごとの明細 CSV を出力します。
  帳票名を含めない「ID のみ」オプションも用意しています（個人情報への配慮）

### 改善: 実行状況が見やすくなりました（v0.43.0）

- **持ち越しバッジ**: 上限で打ち切って次回へ持ち越した実行が、一覧で一目で分かります
- **チャンク内訳**: 実行の行を開くと、チャンクごとの期間・件数・状態を確認できます

### 変更: 実行済みフローの対象・宛先は変更できなくなりました（v0.43.0）

一度でも取り込んだ（配信実績のある）フローについて、定義・配信先・期間モード・抽出
フィルタの変更をできないようにしました。これらを後から変更すると、変更後の対象の
過去分が**気づかないうちに欠ける**ためです。別の対象・宛先で取り込みたい場合は、
新規フローを作成し「取得開始日」で過去から取得してください（未実行のフローは
これまでどおりすべて変更できます）。

### 新機能: 安全取得（時間窓分割）— 大きな差分や過去の遡及取得が安心になりました（v0.42.0）

差分の量が大きい場合や、過去（例: 10年前）から順に取り込みたい場合に、期間を小さな
実行単位（チャンク）に分けて順に取得できるようになりました。フロー作成の
「安全取得（時間窓分割）」から有効にできます（既定はオフ。従来の動作は変わりません）。

- **取れた分だけ確実に進みます**: チャンクごとに配信・検証して記録を進めるため、
  途中で失敗・中止しても、済んだ分の取り直しはありません
- **多すぎる窓は自動で半分に**: 窓の件数がしきい値（既定500件）を超えるときは、
  その窓を自動で半分に分けてから取得します。繁忙期などで偏りがあっても、
  1回の仕事の大きさが膨らみません
- **過去からの遡及取得（バックフィル）**: 取得開始日を指定すると、そこから現在までを
  「1回の実行あたり4チャンクまで」のように小分けで進められます。日次スケジュールと
  組み合わせれば、毎日少しずつ自動で追いつきます

### 修正: 対象0件の実行の送信先表示（v0.42.0）

対象0件で配信物がない実行について、送信先が「不明（台帳を参照）」と表示されていたのを、
「対象0件（配信なし）」と正しく表示するようにしました。

### 新機能: プロジェクトで現場スキルが使えるようになりました（v0.41.0）

Ontology Studio で人が確認・確定した「現場スキル」（帳票の見方・運用ルール）が、
**プロジェクトのチャットでも使えるようになりました**。これまでは現場AIチャットだけで
使えていた機能です。

- **自動で渡ります**: 自分のテナントを読み取り元にしたプロジェクトなら、確定済みの現場スキルが
  会話のたびに最新の内容で渡されます。特別な設定は不要です
- **参照の根拠に「現場スキル」の行**: 回答の下に、渡した現場スキル名と、実際に**開いた形跡が
  あるか**が出ます。「使った」とまでは言い切らず、観測できた事実だけを表示します
- **プロジェクトごとに外せます**: プロジェクト一覧の「現場スキル ● 件」バッジから、
  このプロジェクトでは使わない現場スキルを選べます（既定はすべて使う）
- **フォルダへ書き出せます**: お使いの素の Claude Code / Codex CLI でも同じ現場スキルを使いたい
  場合、フォルダへの書き出しボタンで実体を配置できます。書き出した内容には項目の意味・運用ルール
  （人が確認したラベル情報）が含まれ、帳票の値は含まれません

### 改善: 「読み取り元の状態」の表示を分かりやすくしました（v0.41.0）

プロジェクトチャットの状態表示が開発用語のまま出ていた箇所を、現場蓄積データ画面と同じ言い方
（「検索できる」「一部使える（検索に制限）」など）に揃えました。

### 新機能: プロジェクト — フォルダを正本にエージェントと作業する（v0.40.0）

**手元のフォルダを「プロジェクト」として登録**すると、そのフォルダを作業場所にして
Codex または Claude と会話できます。エージェントはフォルダ内のファイルを読み書きし、
選んだ読み取り元の現場データを参照（読み取りのみ）します。

- **登録・解除**: 登録しても、フォルダやその中のファイルは移動・削除されません。解除も台帳から
  外すだけです
- **データの読み取り元**: 自分のテナント／共有／API から選びます。新規登録では
  現在の接続先が自動で入ります
- **AGENTS.md と読み取りスキル**: 何が置かれるかを確認してから配置できます。既存のファイルは
  上書きしません
- **チャット**: Codex / Claude を切り替えられます。会話履歴は画面のメモリだけに保持され、
  画面遷移やアプリ終了で消えます
- **参照の根拠**: 返答の下に、使ったデータセット・件数・読み取りが途中で切れたかどうかが出ます。
  `complete`（完了）／`partial`（一部のみ）／`semantic only`（意味情報のみ）／`unknown`
  （完了性を確認できない）は、エージェントの自己申告ではなく**実際の読み取り記録から判定**します
- **準備状況**: 入力欄の上に、参照できるデータセットの状態を表示します（帳票の値は表示しません）
- 現場AIチャットからも「プロジェクト」ボタンでプロジェクトのチャットを開けます

読み取り元が現在の接続先と合わないときは、理由を表示してチャットを開始しません。

### 改善: 現場データを読むための知識をエージェントへ段階的に渡せるようになりました（v0.40.0）

エージェントが「配信済みデータをどう安全に読むか」を、必要な分だけ参照できるようになりました
（i-repo 2.37.0）。読み取り専用の規約・時刻の扱い・PII の扱いなどを、質問に応じて必要な項目だけ
読み込みます。プロジェクトには読み取り用のスキルを配置でき、同じフォルダを CLI から開いても
そのまま使えます。

### 重要な修正: エージェントの応答が途中までしか表示されない場合がありました（v0.40.0）

プロジェクトのチャットで Codex を使ったとき、**応答が複数に分かれると 2 つ目以降が表示されない**
問題を修正しました。

### 安全性の強化（v0.40.0）

エージェントに渡す権限を、必要な範囲へ絞り込みました。

- 現場データを読む道具は、**読み取り専用と確認できるものだけを明示的に許可**する方式へ変更
  （従来はまとめて許可していたため、将来書き込み用の道具が増えると自動的に使える状態でした）
- スキルの記述に含まれるコマンドが、**エージェントの許可設定を経由せずに実行される**経路を塞ぎました
- データを読む補助プロセスの作業場所を専用領域に固定し、**プロジェクトフォルダが間接的に
  汚れない**ようにしました

### そのほかの修正（v0.40.0）

- 一覧の接続先 ID（64 桁）を畳んで表示（値はマウスを乗せると確認できます）
- データセットを ID だけでなく名前（例: `SqliteFlow → sqlite`）で表示
- 用語を「データの読み取り元」「接続先 ID」に整理し、直接入力は折りたたみに
- 読み取り API に集計（aggregate）エンドポイントを追加
- 読み取り API の認証失敗・権限外アクセスを監査記録に残す
- UI 言語を切り替えたあとの一部の文言が古い言語のままになる問題を修正

## 2026年7月

### 重要な修正: 帳票定義で絞ったフローが、選んでいない帳票まで配信していました（v0.39.0）

フローの「**帳票定義ID（topId）**」欄に定義を入れて絞ったつもりでも、**その指定が抽出に
渡っておらず、選んでいない定義の帳票と PDF まで配信先に書かれていました**。さらに、データの
記録（カタログ）には「この定義のデータセット」と載るため、**記録と中身が食い違う**状態でした。

指定が抽出コマンドまで確実に届くよう修正しました。絞り込みの規則は記録側と**同じ1つの実装**を
使うため、今後この食い違いは構造的に起きません。

- 抽出設定の「帳票定義ID」フィルタ（`--definition-id`）を使っていた場合は影響ありません（従来から正しく効いています）
- 削除フローも影響ありません（従来から正しく絞られています）

この問題は、外部テスターによる受け入れテスト（20 シナリオ・全手動）で発見されました。

### 改善: 同時配信でも「配信レポート」が出るようになりました（v0.39.0）

複数の送り先へ同時配信したとき、配信レポート（**ファイルごとの SHA-256 ハッシュ・生成プラグイン・
失敗の内訳**）が空になっていました。単一の送り先と同じ内容が出るようになりました。

- ハッシュの対象は「**配った時点のバンドルの中身**」です（配達の記録ファイルは含めません）
- 送り先ごとの失敗理由も一覧に出ます（これまでは失敗した実行でも「失敗: なし」と表示されていました）

### 改善: 現場 AI が、画面の言語で答えるようになりました（v0.39.0）

英語表示にしていても現場 AI が日本語で回答していました。画面の言語に追従して答えます
（末尾の「提案」チップも同様です）。

### 新機能: フローの設定を、ファイルで持ち出し・持ち込みできるようになりました（v0.38.0）

**パソコンを新しくするとき**、これまではフローを1本ずつ手で作り直すしかありませんでした。
設定ファイルをコピーする方法も、**新しいパソコンでは一覧に出ない**（接続先が違うため）ので
実質使えませんでした。

フロー画面の「**書き出し**」で設定を1つのファイルに保存し、別のパソコンで「**読み込み**」すれば
移せるようになりました。読み込みは**まず内容を確認する画面**が出て、そこで「何が作られるか」
「何が既存のものを使い回すか」「あとで入れ直すものは何か」が分かってから実行できます。

**秘密の扱い**（持ち出すファイルなので慎重にしています）

- 「環境変数から読む」にしている資格情報は**そのまま運べます**（値ではなく変数名だけなので安全です）
- 直接入力した資格情報は**ファイルに含めません**。読み込み後に「再入力が必要」として一覧で示します
- Webhook の鍵や「前回どこまで取ったか」の位置は**運びません**（鍵は読み込み先で作り直されます）

**移行でつまずきやすい点も先に知らせます**

- `/Users/…` のようなパスは移行先に無いことがあるため、「このパスは存在しないかもしれません」と
  読み込み前に一覧で示します
- **スケジュール実行は、読み込み後に「スケジュール」画面で OS タスクへ登録し直してください**
  （設定は運ばれますが、OS への登録は移行先には存在しません）
- **Webhook で起動していたフローは、起動 URL が変わります。** 安全のためキーは移行先で
  新しく発行されるので、**外部システムや OS タスクに登録してある URL を新しいものに
  更新してください**（古い URL では起動しません）

どちらも結果画面で「次にやること」として、対象のフロー名つきで案内します。

同じような設定のフローを**複製**したいときや、設定の**バックアップ**にも使えます。

### 新機能: 送り先の資格情報を、アプリに保存せず「環境変数」で持てるようになりました（v0.37.0）

送り先のパスワードや APIキーは、これまでアプリの設定データベースに保存していました。パソコンの
バックアップやファイル共有に**資格情報が一緒に含まれてしまう**のが気になる場合に備え、
**値の代わりに「環境変数の名前」だけを保存する**方式を選べるようにしました。

接続先の設定で秘密の欄に「**環境変数から読む**」を選び、変数名（例 `MY_ES_PROD_KEY`）を入れるだけです。
実行のたびにその変数から読み取るので、**アプリの中には値が一切残りません**。

- 変数が設定されていないときは、認証エラーで悩ませず「`MY_ES_PROD_KEY` が設定されていません」と
  はっきり伝えます
- 同じ種類の送り先が複数あっても、それぞれ別の変数名を選べるので衝突しません
- 従来どおり値を直接入力する方式もそのまま使えます（切り替えは任意です）

### 改善: 現場 AI の検索でも、資格情報がコマンド引数に載らなくなりました（v0.37.0）

v0.36.0 で「送り先のパスワードや APIキーが他の人から見えなくなりました」とお伝えしましたが、
**現場 AI（エージェント）がデータを検索する経路だけは対象外**でした。同梱の i-repo CLI 2.36.5 への
更新でこの経路も環境変数渡しになり、**すべての経路**で資格情報がプロセス一覧に出なくなりました。

### 改善: 現場 AI が軽く・溢れにくくなりました（v0.37.0）

### 改善: 同時配信で「実際に何を実行したか」が残るようになりました（v0.36.0）

**配信を始める前に中止**し、どの送り先のどの環境変数がぶつかっているかを表示するようにしました。

### 重要な修正: 複数の送り先へ同時配信すると「配信先」が空欄になっていました（v0.35.1）

**複数の送り先へ同時に配信した帳票**について、データ確認画面の **「配信実績（フロー→配信先）」** が **`—`（空欄）**になっていました。配信は成功しているのに「どこへ出したのか」が記録として見えず、**監査のときに追えない**状態でした。

配信先の情報自体は失われていなかったため、**過去に配信した分もさかのぼって表示されるようになりました**（データの入れ直しは不要です）。

同じ原因で空欄になっていた次の場所も、あわせて直しています。

- **実行状況の詳細**: **「送信先URI」** に、同時配信したすべての送り先が並ぶようになりました
- **概要（ダッシュボード）**: 「最近の実行」の **「送信先」** が出るようになりました（複数のときは先頭 1 件＋「他N件」）
- **現場 AI**: 同時配信した実行について質問したとき、AI が配信先を把握できるようになりました（これまでこの種の実行では配信先の情報が渡っていませんでした）
- 同時配信で**送り先が 1 行にまとめられてしまう**問題も直りました（別々の送り先が別々の行で見えます）

### 改善: 配信先が空のとき、その理由が分かるようになりました（v0.35.1）

**実行状況の詳細・概要（ダッシュボード）・現場 AI** で、配信先が空のときに **なぜ空なのか**を表示するようにしました（これまでは一律 `—` でした）。データ確認画面の「配信実績」は従来どおりの表示です。

- **実行中** — まだ確定していません
- **なし（削除実行）** — 削除メンテナンスの実行には配信先がありません
- **なし（お試し実行）** — ドライランなので送っていません
- **配信されていません** — 失敗したため送り先に届いていません
- **配信なし（ローカルのみ）** — 配信先を設定していないフロー（検証モード）です
- **不明（台帳を参照）** — 上記以外。このときだけ台帳を確認する価値があります

これまでは失敗した実行まで「不明」と表示され、**存在しない記録を探しに行かせてしまっていました**。現場 AI に渡す説明も同じ文言に揃えたので、AI が誤って案内することもなくなります。

### 重要な修正: 自動掃除が「ここにしかないファイル」を消していました（v0.35.0）

配信済みのローカル保存を自動で片づける機能（既定 ON・7 日）が、**送り先にコピーが無いバッチまで削除**していました。次のような配信では成果物（PDF・写真）がこのアプリにしか存在せず、消えると元に戻せません。

- **検索先（Elasticsearch・SQLite など）だけに配信**したもの（検索先にはファイル本体が送られません）
- **複数配信先のうち保管先が失敗**し、検索先だけ成功したもの
- 配信先を指定しない**検証モード**での実行、**お試し実行（dry-run）**
- **配置（placement）**での配信（送り先に目録が残らないため取り戻せません）

これらを**自動掃除の対象外**にしました。あわせて次の点も改善しています。

- 掃除で消えるのは**成果物の実体だけ**になり、配信の記録（目録・受領書）は残ります。そのため掃除後もファイル一覧・「🌐 開く」・「⬇ 保存」がそのまま使えます
- 設定画面に**「掃除できる ○ 件／ここにしかない ○ 件」**の内訳が出るようになりました。「今すぐ掃除」を押すと、実行前に何が消えて何が残るかを確認できます
- 実行状況の詳細で、送り先にコピーが無いバッチには**「⚠ ここにしかありません」**と表示されます（個別に削除する前に気づけます）

  配信のたびに「実際にどの i-Reporter 接続先から取得したか」を、i-repo CLI 自身の申告（来歴）に基づいて
  記録・確認するようにしました。別の接続先のデータを取り違える事故を、仕組みとして防ぎます。接続先が
  はっきりしないまま実行されるフローは、安全のため自動で停止します（接続先を確定してから再実行してください）。
- **接続先の切替まわりを整理**
  以前の「接続先が切り替わりました」通知は、上記のより確実な仕組みに置き換えて廃止しました。
- **内部基盤の一本化**
  プラグイン・データアクセス仕様を i-repo CLI 側に一本化（同梱）し、二重管理をなくしました（通常の操作・
  動作に影響はありません）。

### 新機能

- **現場 AI チャットが画面を移動しても消えない**
  現場 AI チャットの会話が、別の画面（実行状況・現場蓄積データ など）へ移って戻っても**そのまま続く**ように
  しました。回答の生成中に他の画面を確認しに行っても、戻れば続きが見られます（接続先を切り替えたときだけ
  リセットします）。
- **データや実行状況から、その場で AI に相談**
  「現場蓄積データ」のデータセット／個別の帳票、「実行状況」の実行詳細に**「🤖 AIに相談」ボタン**を追加。
  押すと、その対象（どのデータセット・帳票・実行か、絞り込み条件）を引き継いだ状態で現場 AI チャットへ移動し、
  すぐ質問できます。引き継ぐのは識別子・条件だけで、**帳票の中身や個人情報は送りません**（AI が必要に応じて
  読み取り専用で取得します）。
- **アーカイブの保存先フォルダ名を自由に**
  S3 / GCS / Azure / ファイルサーバーへアーカイブを送るとき、保存先の**フォルダ名を自由に決められる**ように
  しました（これまでは実行ごとの英数字IDフォルダ固定）。配信先設定の「保存先サブパス」に入力でき、
  `{date}`（日付）・`{flow}`（フロー名）・`{datetime}`（日時）・`{batchId}` の**差し込みチップ**をクリックで
  挿入できます（例「点検記録/{flow}/{date}」→ `点検記録/設備点検/2026-06-23/…`）。
- **クラウドに送ったデータを取り戻す**
  S3 / GCS / Azure へ配信したアーカイブを、実行状況の画面から**「☁ クラウドから取得」ボタン**でローカルへ
  取り戻し、中身（PDF 等）をプレビュー／保存できるようにしました（読み取り専用＝送信先は変更しません）。
  ローカルを掃除した後でも、いつでも取り戻して確認できます。
- **接続先（テナント）ごとに表示を分離**
  複数の i-Reporter 接続先を切り替えて使う運用で、**選んだ接続先の情報だけ**が全画面（概要・フロー作成・
  実行状況・スケジュール・データ確認・現場蓄積データ・現場 AI チャット）に表示されるようにしました。
  接続先を切り替えると、画面・チャットがその接続先の内容に切り替わります。**別の接続先のデータが混ざって
  見えることはありません**（接続先が確認できない記録は、明示的に現在の接続先へ紐付けるまで表示しません）。
- **新しいバージョンのお知らせ**
  アプリに**新しい版が公開されると、サイドバーに「↑ 新版 vX.Y.Z あり」**と表示されます。
  クリックするとダウンロードページが開きます（自動更新はしません・お知らせのみ）。これで
  最新版を見逃しにくくなります。
- **定期実行（スケジュール）**
  フローを時刻・曜日で**自動実行**できるようになりました。フローで頻度（毎日／毎週／間隔）を
  決め、スケジュール画面のカレンダーから OS のスケジューラ（Windows: タスクスケジューラ /
  macOS: launchd / Linux: cron）へ登録します。
- **クラウド転送に Google Cloud Storage / Azure Blob を追加**
  これまでの Amazon S3 に加え、アーカイブを **GCS / Azure Blob Storage** へもアップロードできます。
- **アーカイブをローカル/ファイルサーバーへも保存**
  クラウド（S3 / GCS / Azure）だけでなく、**指定フォルダやファイルサーバー（ネットワーク共有）**へ
  アーカイブを保存できるようになりました。接続先テンプレートで「archive」を選び、保存先のパス
  （例: 共有フォルダ）を入れるだけ。専用の外部ツールは不要です。
- **現場 AI チャット（Claude / Codex 対応）**
  アプリの中で、現場データについて **AI に日本語で質問**できます（読み取り専用。お手元の AI を
  そのまま使う形）。**Claude（Claude Code）** に加えて **Codex（OpenAI Codex）** も選べるように
  なりました（画面上部で切り替え）。Codex は安全のため読み取り専用で動きますが、ツールの絞り込みが
  Claude より緩いため **試験的対応** の位置づけです（常用は Claude をおすすめ）。
- **テキストのみ取得**
  PDF / Excel のファイルは取らず、**項目の入力値（テキスト）だけ**を軽く取り込むモードを追加。
  検索・分析が目的のときに高速・軽量です。

### 改善

- **「現場AIチャットへ」の導線を整理**
  データ／実行から現場 AI チャットへ移動するボタンの表記を **「現場AIチャットへ」** に統一しました。
  また、実行が**進行中（実行中）のときはこのボタンを出さない**ようにしました（結果が出てから相談できます）。
- **配信先を種別ごとに整理**
  送り先を「データベース / データレイク / クラウドDWH / 検索 / アーカイブ」などの種別で
  グループ表示し、目的の送り先を見つけやすくしました。
- **「プラグイン」タブの使い勝手**
  表示を高速化し、各プラグインの「フォルダを開く」「アンインストール」を追加しました。
- **プラグインの更新に気づける**
  アプリに同梱された新しい版がインストール済みより新しいとき、「プラグイン」タブで
  「更新あり」を表示するようにしました（ネット接続なしでも判定）。ワンクリックで最新へ更新できます。
  ※ 例えばアーカイブの送り先に Google Cloud Storage / Azure Blob / ファイルサーバーが
  増えても、更新すれば選べるようになります。
- **状態バッジから対処へ**
  「版が変わった」「出所が確認できない」などのバッジを押すと、対処方法やマニュアルへ案内します。
- **使い方ガイドを刷新**
  専門用語を整理し、よりわかりやすい説明に。仕組みの詳細は各ページ末尾の「技術メモ」にまとめています。
- **接続先の切り替え・復活を安全に・気づける形で**
  i-Reporter の接続先が **切り替わった**ときに気づけるよう、画面でお知らせ＋ワンクリックで各フローを
  新しい接続先へ付け替えできるようにしました。接続先に **つながらない**間は、データ確認画面の
  削除・紐付けなどの操作を自動で保留し（うっかり別サーバーの記録を消さないように）、**復活すると
  自動で元どおり**になります。接続先は名前で表示し、別サーバー由来・出所不明の記録を区別します。
- **「いまの接続先」ごとの表示に統一**
  概要・フロー作成・実行状況・スケジュール・着信 Webhook を、**いまつないでいる接続先のもの**に
  絞って表示するようにしました。接続先を切り替えると、これらの画面がいっせいにその接続先の内容へ
  切り替わります。概要の上部には**接続先のドメイン**を表示し、どの接続先の状況かが一目で分かります。
  （接続先テンプレート・クリーンアップ設定・プラグインなどは接続先に依存しないため全体表示のままです。
  すべての実行履歴は「実行状況」画面で確認できます。表示の出し分けのみで、データは消えません。）
- **詳細ドロワーを広く**
  データ確認などの詳細パネル（右からせり出すドロワー）の横幅を大きくし、情報を見やすくしました。

### 修正

- **配信済みなのに「データが無い」と表示される問題を修正（重要）**
  i-Reporter の接続先によっては、配信が成功しているのに「現場蓄積データ」や「現場 AI チャット」で
  データセットが 1 件も出ない（AI が「データがありません」と答える）ことがある問題を修正しました。
  接続先の識別方法のずれが原因で、本番のサーバー設定でほぼ常に起きていました。**過去に配信済みのデータも、
  再配信なしでそのまま見えるようになります。**
- **BigQuery への配信を安定化**
  すでに用意済みのデータセットに送るとき、配信が失敗してしまうことがある問題を修正しました。
- **接続先の切り替え時にログインが保存できない問題を修正**
  接続先を切り替えるとき、「接続テストは成功するのに『検証して保存』で認証に失敗する」現象を
  解消しました。テストと保存が同じ確認を行うようになり、入力した接続先・ユーザー・パスワードを
  そのまま検証して保存します（誤った情報を入れても、動作中の接続設定は壊しません）。
- **Windows で現場 AI チャット（Codex）がデータを読めない問題を修正**
  Windows で Codex を選んだとき、AI が現場データの読み取りツールを使えない／呼び出しが取り消される
  問題を解消しました（読み取り専用は維持）。
- **Mac でアプリから i-repo CLI が見つからない問題を修正**
  i-repo CLI を入れているのに「CLI が見つかりません」と表示されることがある問題を解消しました。
  アプリのアイコンから起動した場合でも、nvm / pnpm / Homebrew などで入れた CLI を正しく見つけます。
- **接続先が未設定のときのダッシュボード表示を整理**
  接続先（i-Reporter）が未設定のときは、概要画面で連携状況の数字を出さずに「接続先を設定する」案内を
  表示するようにしました（これまでの実行履歴は消えません・表示の出し分けのみ）。
- **Mac でアプリから Node.js が「未検出」になる問題を修正**
  Node.js（22.5 以上）を入れているのに、アプリのアイコンから起動すると現場 AI チャット／エージェント
  接続の準備状況で「未検出」と表示されることがある問題を解消しました（i-repo CLI の検出と同じ仕組みに
  そろえ、nvm / pnpm / Homebrew などで入れた Node.js も見つけます）。
- **長い帳票名のアーカイブ取得が失敗する問題を修正**
  帳票名が長い（日本語などを含む）と、PDF/Excel の取得が「name too long」エラーで失敗することがある
  問題を解消しました。あわせて、アーカイブ内のファイル名を **「帳票ID_帳票名」で統一**し、一覧で
  見つけやすくしました。
- **破壊的操作の確認で同じ項目が重複表示される問題を修正**
  アーカイブのクリーンアップ確認ダイアログで、同じ注意（クリーンアップ）が複数回表示される問題を
  解消しました。

### 配布

- **macOS アプリを署名・公証（Gatekeeper 警告が出ない）**
  macOS 版を **CIMTOPS の Developer ID で署名し、Apple の公証（notarization）**を通すようにしました。
  初回起動時の「**悪意のあるソフトウェアか確認できません**」という Gatekeeper 警告が**出ずにそのまま開けます**。
- **Windows はオフライン同梱版を既定に**
  ネットが弱い／無い現場でも確実に起動できます（軽量版・要ネットも選べます）。
- 公開のリリースページから最新版を入手できます。Windows のコード署名は申請手続き中のため、完了までは
  初回起動時に SmartScreen 警告が出ることがありますが、[安全な開き方](manual-setup.html#install-warning)で起動できます。
